### Виды тестирования (тут не все)
##
- Функциональное - проверяет функции программ и компонентов
- Не функциональное - проверяет всё кроме правильности выполнеиния функций: удобство, безопасность, локализацию, поведение под нагрузкой. 
##
- Динамическое - проверяет отработку кода во время его раьоты
- Статическое - проверяет документацию, спецификацию, код-ревью и другие аспекты без запуска и отработки кода
##
- Модульное - проверка определенного модуля или функции или функционала в изоляции от всей остальной программы
- Интеграционное - проверка связи модулей между собой, правильно ли передается и воспринимается информация при передачи данных через посредника
- Системное - проверка системы в сборе без изоляций и исключений, проверка технических требований к продукту
- Приемочное - проверка бизнес-требований к продукту
##
- Черный ящик - проверка бизнес требования к продукту, без (необходимости) знания кода 
- Серый ящик - проверка технических требований к продукту без досканальных знаний кода но при этом взаимодействие проходит с правами недоступными бкдкщим пользователям
- Белый ящик - покрытие кода проверками, требует досканального знания (понмания работы) кода
##
- Альфа-тестирование - проверка программы командой разработчиков 
- Бета-тестирование - проверка программы ограниченным кругом пользователей
##
- Автоматизированное - проверка осуществляется при помощи программ которые сами проводят тест кейсы
- Ручное - человек сам выполняет определенную последовательность действий и сравнивает поведение с предполагаемым
## 
- Смок-тестирование - проверка основных функци продукта после внедрения нового функционала
- Регрессионное - проверка всех функций имеющих прямую связь с внедренным функционалом
- Санити-тестирование - проверка внедренного функционала на предмет багов
