# Принципы тестирования (ISTQB/ISO 29119)

Основные правила эффективного тестирования программного обеспечения.

## 1. Тестирование показывает наличие дефектов, но не их отсутствие
- **Суть:** Тесты выявляют ошибки, но не могут доказать их полное отсутствие
- **Следствие:** 100% покрытие тестами ≠ 100% надежность
- **Пример:** Даже после 1000 успешных тестов в системе могут остаться скрытые дефекты

## 2. Исчерпывающее тестирование невозможно
- **Суть:** Невозможно проверить все комбинации входных данных и сценариев
- **Решение:** Применять техники тест-дизайна:
  - Эквивалентное разделение
  - Анализ граничных значений
  - Таблицы решений
- **Пример:** Для поля "Возраст" (1-100 лет) проверяем:
  - Границы: 0, 1, 100, 101
  - Типовое значение: 50

## 3. Раннее тестирование экономит время и деньги
- **Суть:** Дефекты дороже исправлять на поздних этапах
- **Методы раннего тестирования:**
  - Анализ требований
  - Статическое тестирование
  - Прототипирование
- **Выгода:** Нахождение ошибки в ТЗ в 100 раз дешевле, чем в коде

## 4. Кластеризация дефектов (Defect Clustering)
- **Суть:** 80% ошибок сосредоточены в 20% модулей (принцип Парето)
- **Практическое применение:**
  - Фокус на сложных компонентах
  - Приоритезация тестирования рискованных модулей
- **Типичные "кластеры":**
  - Интеграционные точки
  - Сложная бизнес-логика
  - Новый/измененный код

## 5. Парадокс пестицида (Pesticide Paradox)
- **Суть:** Повторяющиеся тесты перестают находить новые дефекты
- **Решение:**
  - Регулярный ревью тест-кейсов
  - Exploratory testing
  - Ротация тестировщиков
- **Методы обновления тестов:**
  - Добавление новых сценариев
  - Изменение тестовых данных
  - Использование новых техник

## 6. Тестирование зависит от контекста
- **Суть:** Подход к тестированию определяется:
  - Типом продукта
  - Бизнес-требованиями
  - Рисками проекта
- **Примеры различий:**
  | Система           | Акцент тестирования          |
  |-------------------|-----------------------------|
  | Банковское ПО     | Безопасность, точность данных|
  | Мобильная игра    | Производительность, UX      |
  | Медицинское ПО    | Надежность, соответствие стандартам|

## 7. Заблуждение об отсутствии ошибок
- **Суть:** Бесполезная система без багов ≠ полезная система
- **Критерии успеха:**
  - Соответствие потребностям пользователей
  - Решение бизнес-задач
  - Удобство использования
- **Пример:** Идеально работающее приложение без нужного функционала не будет востребовано
